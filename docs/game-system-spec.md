# CODE MONSTERS ゲームシステム仕様

## 1. 体験の核

ショップでモンスターを集め、特殊配合で新しい固有特性と3スキル構成を作り、3体編成のシナジーを考えるラン制オートバトラーとする。

戦闘中の直接操作は行わない。勝敗は次の準備で決まる。

1. 3体それぞれの固有特性をどう組み合わせるか
2. 攻撃・回復・防壁・強化・妨害・加速の役割をどのスキルで補うか
3. そのスキルをどの条件・対象で使うか
4. 欲しい配合限定種から親を逆算し、ショップで揃えるか

星、レベル、経験値、成長曲線、成熟待ち、孵化は設けない。入手した個体と配合した子は即座に完成状態で使える。時間経過による強さではなく、編成判断にプレイ時間を使わせる。

## 2. ユーザージャーニー

1. 3回の初期ドラフトで主力3体を選ぶ
2. 編成画面で特性・3スキル・役割の空きを比較する
3. 配合図で欲しい固有特性と必要な親2体を先に確認する
4. ショップで不足する役割、配合の親、装備を購入する
5. 特殊配合が成立したら、子の固定特性を確認する
6. 親1・親2・子のスキル候補から3つを選び、子を完成させる
7. ガンビットを整え、3対3の自動戦闘へ進む
8. 戦闘後は成長処理を挟まず、すぐ次の編成判断へ戻る
9. 最大12サイクル、または5敗まで繰り返す

## 3. モンスター

### 3.1 分類

- 系統: 竜、悪魔、精霊
- 属性: 光、闇、火
- 属性は分類と視覚表現にのみ使い、相性・耐性・命中補正を持たない
- 基本カタログ: 3系統 × 3属性 × 5種 = 45種
- 5種は上下関係のあるランクではなく、異なる固有特性・能力配分・スキルを持つ別種
- 追加モンスター: 経済や編成テーマを広げる5種

45基本種のうち18種をドラフト／通常ショップで入手できる店頭種、27種を特殊配合限定種とする。

### 3.2 個体状態

個体が保持する状態は次だけとする。

- 安定した個体ID
- モンスター種ID
- 選択済みスキルID 3つ
- ガンビット2〜6ルール
- 装備ID 0〜1つ

レベル、経験値、星、成長値、個体値、保持サイクル数は保存しない。

### 3.3 固有特性

- 特性はモンスター種へ固定する
- 配合で継承・選択・変更しない
- 段階成長を持たない
- 現行プロトタイプでは開戦時効果としてデータ駆動で解決する
- UIではモンスター名と同じ優先度で常に表示する

## 4. スキル

### 4.1 スキル枠

- 1体は重複しない3スキルを持つ
- 通常攻撃は3枠へ含めない
- ドラフト／ショップ個体は種ごとのネイティブ3スキルで加入する
- 配合後の個体は配合時に選んだ3スキルを持つ

### 4.2 配合時の選択候補

候補集合は次の和集合とする。

```text
親1が現在持つ3スキル
∪ 親2が現在持つ3スキル
∪ 子のネイティブ3スキル
```

- 候補の重複は1つへまとめる
- 候補から重複しない3つを必ず選ぶ
- 親が過去の配合で得たスキルも次世代へ渡せる
- 子のネイティブスキルを0〜3個選べる
- 確定後は選択した3スキル用の初期ガンビットを生成する

## 5. 特殊配合

### 5.1 基本ルール

- 通常配合と同名配合は設けない
- `game.json` に記述された特殊配合レシピへ親2体が一致した場合だけ配合できる
- 親の順序は問わない
- 配合は両親を消費する
- 親の装備は自動で装備庫へ戻す
- 子は即座に完成状態で加入する
- 配合成立時に1コインを得る
- 複数レシピが成立する場合はすべて提示する

### 5.2 レシピ構成

- 27の配合限定種はそれぞれ2ルートを持つ
- 合計54レシピ
- すべての親は通常ショップで入手できる18種から選ぶ
- 同じ親ペアを別結果へ重複使用しない
- 配合限定種を次の配合の必須親にしないため、待ち時間の連鎖を作らない

### 5.3 配合UI

確定前に次をすべて表示する。

- 両親と結果種
- 子へ固定される固有特性
- スキル候補ごとの出自（親1、親2、子。複数可）
- 選択中の3つの遺伝子枠
- 両親が消費され、装備が戻り、1コインを得ること

配合図は最初から全公開し、結果種から2通りの親ペアを逆引きできる。発見待ちで計画を妨げない。

## 6. ショップ

- モンスター3枠、装備2枠
- 更新費用1コイン、棚固定あり
- 配合限定種は販売しない
- 商品が手持ちの個体と特殊配合できる場合、金色の予兆と結果名を表示する
- 同じ棚の別商品と特殊配合できる場合も予兆を表示する
- 予兆は装飾だけで終わらせず、どの結果へつながるかを短く明示する

## 7. 編成と装備

- 主力3体、控え最大4体、合計7体
- 主力が3体でなければ戦闘開始できない
- 各個体は装備を1つ持てる
- 装備は基礎能力への補正と開戦時効果を持てる
- 編成画面は6役割（攻撃・回復・防壁・強化・妨害・加速）の充足と空きを表示する

## 8. ガンビット

- 初期3ルール、最少2、最大6
- 上から `条件 -> スキルを含む行動 -> 対象` を評価する
- 条件不成立、MP不足、対象不在なら次のルールへ進む
- すべて不成立なら通常攻撃
- 配合後は選んだ3スキルに合わせた初期ルールへ戻す

## 9. 戦闘

- 決定論的な3対3 ATB
- 乱数は呼び出し側の整数シードだけを使う
- 同じコンテンツ版、入力、シードは同じ結果とリプレイを返す
- MP、会心、盾、強化、弱体、継続効果を扱う
- 45秒から3秒ごとに環境崩壊ダメージ
- 最大66秒
- 戦闘結果は勝者、フレーム、陣営ダメージ、個体別・スキル別の貢献を返す
- 戦闘後に個体能力やスキルを自動変更しない

## 10. ラン

- 初期コイン10
- 各サイクル開始時の収入10
- 最大12サイクル
- 5敗で早期終了
- イベントはサイクル3、6、9
- イベント報酬はコイン、無料更新、希少入荷、装備、コイン賭けに限定する
- 経験値や成長を報酬にしない

## 11. データと再現性

- `src/game/game.json` をコンテンツと調整値の単一ソースとする
- 安定した英語IDを使い、日本語表示文字列で分岐しない
- コア状態とコマンドはJSONへ直列化できるプレーンデータとする
- `src/core/` はReact、DOM、CSS、ストレージ、時計、ブラウザAPIを参照しない
- `Math.random()` をコアで使用しない
- 操作ログはドラフト、購入、編成、装備、ガンビット、配合時の3スキル、イベント、戦闘、サイクル進行を保持する

## 12. 検証項目

- 戦闘後すぐ、次のショップ・配合・編成判断へ意識が戻るか
- 欲しい固有特性から親を逆算できるか
- ショップ予兆が配合計画を助けるか
- 配合時の3スキル選択に、親を集めた意味が残るか
- 子のネイティブスキルを残すか、親の役割を移すかで迷えるか
- 3体の役割カバレッジとガンビットを一緒に考えられるか
- 特殊配合が単なるアイテム合成ではなく、固定特性を持つ新種の獲得として感じられるか
